# M0-3 ｜ 问题报告：sensor_analyzer.py 缺陷分析与修复

> **AI 使用说明**：本修复过程中使用了 AI 辅助分析缺陷和编写修复代码。本人已逐行研究并验证每一处修复，理解每处缺陷的原理和修复逻辑。

---

## 原始脚本意图

1. 读取 `sensor_data.csv`（列：`time`, `value`）
2. 计算 `value` 的平均值、标准差
3. 剔除离群值（`|value - mean| > 2 * std`）
4. 将清洗后的数据保存为 `cleaned_data.csv`
5. 打印统计摘要

---

## 缺陷清单（共 8 处）

| # | 定位（原行号） | 缺陷 | 现象 | 原因 | 修复方式 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 1 | 第 37 行 `row["Value"]` | 列名大小写错误 | `KeyError: 'Value'`，脚本直接崩溃 | CSV 表头列名是小写 `value`，代码访问的是大写 `Value`，DictReader 区分大小写 | 改为 `row["value"]` |
| 2 | 第 33 行 `open(INPUT_FILE, "r")` | 文件句柄未释放 | 无直接报错，但文件句柄泄漏，资源未正确关闭 | `open()` 返回的文件对象未用 `with` 语句管理，读取完毕后不会自动关闭 | 改为 `with open(...) as f:` 上下文管理器 |
| 3 | 第 52-53 行 `acc += (v - mean)` / `std = acc / len(data)` | 标准差计算公式错误 | 标准差恒为 `0.0`，导致后续离群值判定完全失效 | 累加的是偏差本身（`v - mean`），而偏差之和恒为 0（均值的数学定义）。正确做法是累加偏差的**平方**，再除以 N 后开根号 | 改为 `acc += (v - mean) ** 2`，`std = (acc / len(data)) ** 0.5` |
| 4 | 第 57 行 `if v > mean + 2 * std` | 离群值判定条件不完整 | 只剔除偏大的离群值，偏小的离群值（如 `-21.3`）被保留 | 条件只检查了上界 `v > mean + 2*std`，未检查下界 `v < mean - 2*std`。任务要求"同时剔除偏大和偏小的离群值"，即 `|v - mean| > 2*std` | 改为 `if abs(v - mean) > 2 * std` |
| 5 | 第 56-58 行 `for v in data: ... data.remove(v)` | 迭代列表的同时修改列表 | 部分离群值被跳过，未被剔除 | 在 `for v in data` 循环中调用 `data.remove(v)` 会改变列表长度和索引映射，Python 迭代器内部维护的索引会跳过紧邻被删元素的下一个元素 | 不在原列表上删除，改为构建新列表 `cleaned` 收集保留的数据 |
| 6 | 第 61 行 `os.path.join("/", OUTPUT_DIR, OUTPUT_FILE)` | 输出路径写死为绝对路径 | `FileNotFoundError` 或 `PermissionError`：`/out/` 目录不存在 | `os.path.join("/", "out", "cleaned_data.csv")` 拼出的是绝对路径 `/out/cleaned_data.csv`，Linux/WSL 下该目录通常不存在。任务明确要求"不要写死绝对路径，默认写到当前工作目录" | 直接使用 `args.output`（默认 `cleaned_data.csv`），写到当前目录 |
| 7 | 第 65-66 行 `for v in cleaned:` | 输出使用从未填充的 `cleaned` 列表 | 输出文件只有表头行，无任何数据行 | `cleaned = []` 在第 28 行初始化后从未被写入数据。离群值剔除修改的是 `data`（且有 Bug 5 的问题），而输出循环遍历的是空的 `cleaned` | 在离群值剔除时将保留的 `(time, value)` 写入 `cleaned`，输出时遍历 `cleaned` |
| 8 | 第 66 行 `writer.writerow([v])` | 输出只写 value 列，缺少 time 列 | 输出 CSV 每行只有一个数值，与表头 `time,value` 两列不匹配 | `writer.writerow([v])` 只写了一个字段。任务要求输出清洗后的 `time,value` 两列 | 改为 `writer.writerow([t, v])`，同时写入 time 和 value |

## 缺陷之间的依赖关系

> README 中提到"修复顺序存在依赖，前一个不修，后一个的现象会被掩盖"。以下是实际依赖链：

1. **Bug 1（KeyError）** 是第一道阻塞——脚本直接崩溃，后续所有问题都看不到
2. **Bug 6（路径不存在）** 是第二道阻塞——即使修了 Bug 1，写文件时也会因路径不存在而崩溃
3. 修好 1 和 6 后脚本能跑，但 **Bug 3（std=0）** 使 `2*std=0`，导致 **Bug 4（只删偏大）** 的现象被放大——只有恰好等于 mean 的值才被保留
4. **Bug 5（迭代时修改列表）** 会进一步导致部分离群值被跳过
5. **Bug 7（cleaned 为空）** 和 **Bug 8（缺少 time 列）** 即使离群值剔除正确，输出文件仍为空或格式错误
6. **Bug 2（文件句柄泄漏）** 不影响结果正确性，但属于资源管理缺陷

## 额外改进

除修复 8 处原始缺陷外，还增加了以下改进以满足接口契约要求：

1. **命令行参数支持**：使用 `argparse` 支持 `--input` 和 `--output` 参数，同时兼容无参数默认模式
2. **异常输入处理**：文件不存在、空文件、列名不符、非数值内容均给出明确错误信息并以非 0 状态码退出，不抛出栈回溯
3. **BOM 兼容**：读取时使用 `utf-8-sig` 编码，兼容带 BOM 的 CSV 文件
